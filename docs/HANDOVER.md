## 1. What it is, and what it does

A business signs up, publishes its own documents and FAQs, and pastes one script tag
into its website. Visitors get an AI chat that answers **only** from that published
knowledge, cites the passages it used, and hands over to a human when it is not
confident. It is **read-only**: it cannot place orders, issue refunds, or change
accounts. No model is trained on customer conversations.

**Verified end-to-end:** a live turn returns streamed tokens, `declined: false`,
`degraded: false`, a citation, and generated follow-up suggestions.

## 3. How it runs

```
Caddy :80/:443  →  api (FastAPI, 1 uvicorn)  →  postgres+pgvector, redis
                →  dashboard (Next.js)
                →  widget (iframe app, served by api)
                   embed  (BGE-M3, 1024-dim, CPU)  ← one model, shared by ingest + query
                   worker (arq: ingest, purge, alerts)
```

Seven services, `docker compose`. Run from the repo root:

```bash
sudo docker compose up -d          # the operator uses sudo; ubuntu is NOT in the docker group
sudo docker compose ps             # expect 7 healthy
curl -s localhost/api/health       # {"status":"ok"} through Caddy
```

**Secrets** live in `/home/ubuntu/work/eva/.env` (mode 600, gitignored, **never
committed**). Keys: `POSTGRES_PASSWORD`, `EVA_APP_DB_PASSWORD`, `WIDGET_TOKEN_SECRET`,
`OLLAMA_API_KEY`, `LLM_DEFAULT_MODEL`. The GitHub API token for CI polling lives
separately in `~/eva-loop/github.env`.

**Do not:**
- commit `.env`, `~/eva-loop/github.env`, or any key
- add the `ubuntu` user to the `docker` group (the operator flow assumes `sudo`)
- delete `~/.openhands/agent-canvas/secret-key.txt` (settings decryption breaks)
- edit `docs/ARCHITECTURE.md` or `docs/STACK.md` without updating the checksum
  deliberately — that is what the lock is for

## 5. Decisions that will look strange without context

Each is recorded in `docs/PLAN.md` with the reasoning; these are the ones a new reader
will question first.

| Decision | Why |
|---|---|
| **One published knowledge *set* per bot, not a single document** | RAG-11. Publishing is additive; rollback restores the previous **set** atomically or refuses (HALT-10). An earlier design pointed at one `document_version`, which silently dropped every other document on rollback — measured, not guessed. |
| **No Prometheus or Grafana** | HALT-08. Metrics are derived by SQL from tables the app already writes, rendered at `/metrics` in **Prometheus text exposition format**. Adding the stack later is a scrape config, not a rewrite — that forward-compatibility is a tested constraint. |
| **Reranking defaults ON, self-hosted** | HALT-04. Tenant text never leaves the box. |
| **BYOK overrides the platform key** | SEC-04. Tenant keys are read first from the age-encrypted vault. |
| **`/health` is not exposed through Caddy** | §17 does not list it; exposing an unauthenticated probe is a contract change. Uptime monitoring uses the authenticated admin surface. |
| **Legal documents are generated from code** | A test fails if a document drifts from the behaviour it describes. Change the code, regenerate — never hand-edit. |
| **The harness identity `openhands@all-hands.dev` is in history** | Left deliberately. Rewriting 233 commits to hide AI-assisted development would invalidate every recorded SHA for no legal gain. |

## 6. Known limits, stated rather than hidden

- **Retention vs backup:** deleting a conversation does not delete it from a backup taken
  before the deletion. The DPA says so (`backup_retention` marker).
- **Audit log survives erasure** by design — it records that an erasure happened, with
  counts and ids, never content.
- **The query-embedding cache does not make the load gate pass.** 50 unique questions by
  design, so every one was a miss. The gate is evidence about concurrency, not about the
  cache.
- **Email is a local sink** that writes `.eml` files and never delivers. Deliberate for
  testing; a real SMTP provider is a `.env` change at onboarding.
- **The widget needs a verified domain** to serve a new tenant. That is HALT-06's
  mechanism, implemented — a fresh tenant must add and verify their domain first.

**1. Fill the legal markers.** `docs/compliance/MARKER-CHECKLIST.md` lists **46 markers
across 27 fields**, grouped by which milestone each blocks. The commercially blocking
ones: `platform_legal_name`, `platform_address`, `governing_law`, `hosting_sub_processor`,
`hosting_location`, `provider_terms_ollama_cloud`, `provider_terms_deepseek`, `liability`,
`fees_term`, `termination_term`, and the support/abuse/security contacts.

Verify with:
```bash
cd backend/api && python -m app.compliance.render && python -m app.compliance.render_legal
grep -rn '\[\[FILL:' ../../docs/compliance/ | grep -v LEGAL-REVIEW | grep -v 'FILL: \.\.\.'
```
That last command should print nothing.

**2. A lawyer's review.** `docs/compliance/LEGAL-REVIEW.md` sets out what to fix and why,
with sources — **it is not a legal review itself.** The most consequential open question
in it: the EU AI Act **Article 50 applied on 2 August 2026**, and the notice now needs a
section attributing the AI disclosure to it, plus an explicit position on machine-readable
marking of generated output (Art. 50(2)), which is genuinely uncertain for chat answers.

**3. Operational configuration at first onboarding:** a real SMTP provider,
`ALERT_EMAIL`, a domain for TLS, and a decision on whether EVA keeps sharing this box or
moves to its own.

## 8. How the build was run (in case you continue it the same way)

The work was driven by a **per-work-package runner**: a fresh OpenHands conversation per
WP, `max_iterations` 3000, so no turn could exhaust its context. A driver script
(`~/eva-loop/eva_driver.py`) reads the registry, verifies a finished runner (HEAD, clean
tree, pushed, CI verdict), and launches the next row. The 30-minute scheduler was
**stopped on 2026-11-20** when the queue emptied.

Each WP's definition of done was: **tests green → commit → push → CI verdict for that sha
→ registry rows moved → commit hash reported.** A gate report claiming "green" without CI
was treated as a failed gate, twice — and once it was true.

**If you restart it:** re-read `docs/PLAN.md`'s rulings before writing any instruction. The
single most common failure in this project was an instruction written against a stale
state — a hold whose premise had expired, a held-set list that disagreed with the scripts,
or a pulse embedding an out-of-date example. Verify against the repo every time.
